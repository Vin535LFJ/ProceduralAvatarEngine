## 背景

2026-11-24 之前的若干轮以文档为主要交付物。文档是必要的，但它有一个结构性风险：
**文档可以描述一种从未发生过的进展**。一份"架构说明"不需要编译，一份"测试计划"不需要运行，
一份"完成报告"可以引用上一轮的图片。这些都能写得很好，却没有任何一项可以被复核。

同一时期的对照样本说明问题不在文档本身：
`12-poc-sm-vertical-slice.md` 那一轮同时交出了代码（commit `9cdde4c`）、
7 张本轮新生成的灰模、`14/14 suites, 0 failures` 的日志原文、以及一个如实上报的口径问题——
**这一轮的文档之所以可信，恰恰因为它背后有可复核的证据**。

## 决定

采纳负责人指示的全部三条：

1. **交付要求变更**：每轮至少三类实际产出 —— ①代码（可运行实现 + 测试 + 明确 Git Diff）、
   ②视觉证据（本轮新生成的人体图片 / 视角对照 / 几何测量）、
   ③验收结果（测试日志原文 / 失败项 / 参数影响 / 未验证项）。
2. **硬纪律**：一轮工作若没有产生新的可运行代码、真实视觉证据或可复现的技术结论，
   **不构成工程里程碑**。
3. **落地形式**：写成 WorkBuddy 技能（`round-acceptance`），并写入架构 —— 仓库根目录
   `AGENT.md`（权威正文）+ 本 ADR（决策记录）+ SPEC §15 引用。
