## 2. PAE Rig V2 的两个变体（链 A）

| 变体 | 骨骼数 | 组成 | 用途 |
|---|---:|---|---|
| `PAEHumanRigV2-deform` | **102** | 源骨架去掉 59 根面部骨 + 2 根胸骨；含手指（每侧 5 指 × 3 节）、脚趾、扭转骨（`upperarm02 / lowerarm02 / upperleg02 / lowerleg02`）、锁骨 + 肩、5 节脊柱、3 节颈 | 完整人体，含逐指/逐趾 |
| `PAEHumanRigV2-core` | **20** | root、spine01/03/05、neck01、head；每侧 clavicle、upperarm01、lowerarm01、wrist、upperleg01、lowerleg01、foot | 最小可驱动人体（无手指脚趾、无扭转骨） |
| `LegacyRigV1`（生产，未动） | 22 | Root, Hips, Spine, Chest, Neck, Head, L/R Shoulder, UpperArm, LowerArm, Hand, UpperLeg, LowerLeg, Foot, Toe | 现有 Android 路径 |

骨骼数由**动作需求**决定，不由几何决定：20 根即可覆盖肩/肘/髋/膝/腕/踝六个测试关节；手指每增加一节可动指骨就要多一根骨（每侧 +15），扭转骨是 LBS 前臂/小腿扭转时的额外需求。骨骼数与每顶点影响数是两个独立参数：本轮所有组合都用 Top-4。

### 4.1 MakeHuman 权重文件

- 格式：纯 JSON（不是二进制）。`weights.{骨名} = [[顶点, 权重], …]`，0 基索引，同顶点可出现在多组（相加）。与 MPFB2 `weights.md` 的描述一致；MPFB2 文档称 163 组中 24 组为空，本文件是 139 组且全部非空（版本差异，如实记录）。
- 57,107 条；其中 9,464 条属于面部/胸骨，进入 PAE 变形骨架时被丢弃。
- **175 个体表顶点只带面部骨权重**（位置：x ±2.5 cm、y 0.661–0.687 m、z 0.138–0.160 m，即下颌/颏前区域，涉及 226 个四边形）。另有 648 个辅助顶点同样如此。
- 压缩前平均影响数 2.487；Top-4 只丢 0.575 % 质量。
- 数据瑕疵：少数顶点带有跨中线的杂散权重（如右膝外侧一个顶点带 1 % 的左小腿骨权重），见 §8。

### 4.2 无权重顶点的回退规则（本轮新增，已实现并测试）

丢弃面部骨之后没有权重的顶点，按下述两条确定性规则处理（`readMhWeights` 的可选参数：源骨架层级 + 静止位置；不传则保持旧行为、留空）：

| 规则 | 触发条件 | 做法 | 本轮命中 |
|---|---|---|---:|
| `kept-ancestor` | 该顶点在源文件里有权重，但全部落在被丢弃的骨上 | 每根被丢弃的骨替换为它在**源骨架层级**里最近的保留祖先（面部骨全部解析到 `head`），质量合并 → Top-4 → 归一化 | 体表 175 + 辅助 648 |
| `nearest-bone` | 该顶点在源文件里没有任何可用条目 | 绑定到静止姿态下最近的骨段 | 0 |

结果：回退后**没有任何稳定顶点 ID 无权重**。每顶点使用的规则写进模板（格式 2），测试 T10d–T10m 覆盖：175 这个计数、全部绑到 `head` 且权重为 1、已有保留骨权重的顶点不被改动、这些顶点随 `head` 刚性运动、以及一个合成骨架上的两条规则。

**未改动**：同时带保留骨和面部骨权重的 4,239 个体表顶点，仍然只保留保留骨那部分并重新归一化（面部那部分被丢弃）。

### 4.3 PAE 自生成权重（Host，无外部代码）

- **距离法**：到骨段的逆平方距离，候选骨限制在“最近骨距离 + 一个局部骨半径”之内（骨半径 = 该骨最近顶点的距离中位数），在网格图上做两轮拉普拉斯平滑，归一化，Top-4。快（30 ms），但候选骨多，Top-4 丢弃 12.9 % 质量——说明影响分布过宽。
- **热扩散法**：在均匀权重的网格图上解 `(I + tL)h = e`（t = 8，60 次 Jacobi 迭代，**不是** cotangent 权重），按每根骨的最大值归一化，4 次幂，归一化，Top-4。丢弃质量几乎为 0，但慢（436 ms），且与 MakeHuman 权重的一致率并不更高。
- 两种方法与 MakeHuman 权重的主导骨一致率都只有约 60 %。从姿势结果看（§5），MakeHuman 权重在肩、髋两个最难的关节上最好。
- **未做**：Bounded Biharmonic Weights、Harmonic 权重、现有权重从别的网格迁移、cotangent 权重。

## 5. 基础动作（链 A，Host LBS，Top-4）

翻面 = 相对静止姿态法线点积 < 0 的面数（共 13,378 面）；边 p99 = 99 % 分位的最大拉伸或压缩倍数。探针 = 该动作最末端关节的位移（米）。

| 动作 | A. MakeHuman + 102 | B. PAE 距离 + 102 | C. PAE 热 + 102 | D. MakeHuman 重映射 + 20 |
|---|---|---|---|---|
| bind | 翻面 0 | 0 | 0 | 0 |
| 肩外展 70°（腕 +0.085 / +0.405） | 翻面 **0**，边 0.443 / 3.186 | 1，0.518 / 10.231 | 15，0.232 / 5.697 | 0，0.443 / 3.186 |
| 屈肘 90°（腕 +0.240 / −0.048） | **12**，0.276 / 2.208 | 10，0.596 / 1.507 | 15，0.591 / 1.638 | 12，同 A |
| 髋屈 60°（膝 +0.218 / +0.351） | 翻面 **1**，0.307 / 2.038 | 0，0.413 / 3.630 | 19，0.265 / 4.193 | 1，同 A |
| 屈膝 70°（踝 +0.232 / −0.307） | 6，0.207 / 1.579 | **5**，0.610 / 1.584 | 16，0.170 / 1.994 | 6，同 A |
| 腕扭转 60°（指尖 −0.024 / +0.051 / +0.034） | 0 | 0 | 0 | 无指骨，不适用 |
| 踝跖屈 25°（趾 −0.060 / −0.035） | 0 | 0 | 0 | 无趾骨，不适用 |
| 握拳（左，指间关节各 50°） | **714** | 603 | 696 | 无指骨 |

结论：

1. **MakeHuman 权重可以直接使用**，在肩、髋、膝上翻面最少。屈肘 90° 时三种权重都有 10–15 个翻面（肘尖处的四边形在 90° 屈曲下互相穿插），属于基础网格 + 纯 LBS 的固有限制。
2. PAE 自己生成的两种权重**可用但不如**源权重；距离法在肩外展下有一条边拉伸 10 倍，需要收紧候选骨范围或增加平滑。
3. 20 骨 core 骨架重映射 MakeHuman 权重后，在躯干和四肢大关节上的结果与 102 骨完全一致（肘、髋、膝数值逐项相同）。手指、脚趾、腕/踝的细动作在 core 上不存在。
4. **握拳不成立**：指间关节各屈 50° 时约 700 个面翻面，与权重来源无关。原因是基础网格手指每节只有很少几圈环线，纯 LBS 无法表达掌侧皮肤的挤压。逐指动作本来就是 MVP 非目标；若将来要做，需要手掌局部加密 + corrective。
5. 左右独立：左肘屈曲时右侧所有顶点位移 < 1e-7 m（float32 权重舍入），见 T11d。
6. **未测量**：自相交（肩/腋、腹股沟、膝）、Dual Quaternion Skinning、姿势修正形态、扭转骨之间的扭转传递。

## 6. 与 LegacyRigV1 的兼容关系（只分析，未实施）

- 现有 `UBO[22]` 装不下 102 骨；20 骨 core 在**数量上**能装进 22 个槽位，但骨骼语义不同（core 有锁骨、3 段脊柱、无脚趾），BoneId 映射不是一一对应，所以仍然需要新的蒙皮路径，不能直接复用 LegacyRigV1 的调色板。
- 现有 64 B 顶点打包（pos/normal/joints×4 u16/weights×4/color）本身不限制骨骼数，限制来自 UBO 的 `mat4 uBones[22]`。
- 进入 Android 的兼容路线属于 VR-1B 的范围（见 R8），本轮没有任何 Android 验证。

| 方法 | 成本 | 质量证据 | 判断 |

| 直接使用已许可权重（MakeHuman，需回退规则） | 解析 52 ms | 肩 0 / 髋 1 / 膝 6 翻面 | **本轮最优**；前提是 R1 的许可证待决项获批 |

| Bounded Biharmonic | 需要稀疏线性求解器 | 未运行 | 不建议为此引入完整 FEM 依赖 |
| 从现有权重迁移（包络/测地） | 未运行 | — | 换网格时再研究 |

建议：第一轮采用“已许可原始权重 + Top-4 压缩 + 无权重顶点回退规则”（已实现）；PAE 自生成权重保留为无许可权重可用时的 fallback，并优先改进距离法。

## 8. 链 B：官方 163 骨骨架原样加载

链 B 不剔除面部骨，因此不需要回退规则；它的作用是从另一条路径验证“可变骨骼容器 + 官方权重迁移 + 层级旋转 LBS”。

| 项 | 结果 |
|---|---|
| 骨骼 | 163（容器不固定骨骼数） |
| 有权重的体表顶点 / 非法权重 | 13,380 / 0；归一化最大误差 1.79e-7 |
| 压缩前最大影响数 | 9 |
| Top-4 的 L1 损失 | 平均 1.66 %，最大 0.60（至少一个高影响顶点被显著压缩；本轮没有定位它，也没有测动作位置误差） |
| Bone Roll / Rest Transform | 未解析；绕世界轴旋转 |

8 个动作，每个带方向断言（末端关节位移在指定世界方向上的分量下限、转动骨自身的头关节不漂移、镜像侧关节位移 < 0.01 mm、屈肘/屈膝时末端向躯干靠近 ≥ 8 cm）。日志 `DIRECTION_CHECK actions=8 failed=0`：

| 动作 | 定义 | 末端关节位移 / 判据 |
|---|---|---|
| 左 / 右 / 双臂外展 | `upperarm01.L/R` 绕 Z ∓75° | 腕 +0.462 m（竖直）、±0.075 m（向外）；镜像关节 0 |
| 屈肘 | `lowerarm01.L` 绕 X **−85°** | 腕仍在肘前方 11.8 cm；腕到肩（`upperarm01.L` 头）的距离缩短 12.7 cm |
| 髋屈 | `upperleg01.L` 绕 X −50° | 足 +0.612（前）/ +0.273（上） |
| 屈膝 | `lowerleg01.L` 绕 X +60° | 足 −0.309（后）/ +0.216（上）；足到髋的距离缩短 13.1 cm |
| 腕部旋转 | `wrist.L` 绕世界 Y +45° | 手部 1,550 个顶点绕 Y 穿过腕关节扭转 45°。**这不是沿前臂轴的扭转**，只是绕世界竖轴的旋转 |
| 踝旋转 | `foot.L` 绕 X +30° | 趾 −0.061（下）/ −0.046（后） |

- **屈肘方向修正（本轮）**：原版是绕 X **+85°**，实测让左手向后移 0.336 m、向下 0.070 m——把肘向后掰直（过伸），而不是屈肘。原日志只检查“数值有限”，所以 `max_displacement` 新旧两版完全相同（0.488585），仅凭位移大小不可能发现。改为 −85° 并加断言后通过；反向对照（把 +85° 编一个临时版本）断言报 `FAIL`、退出码非 0。
- **对侧渗漏（本轮发现，源数据瑕疵）**：髋屈 50° 时右侧肢体表面最大位移 1.9 mm、屈膝 0.9 mm、踝 0.2 mm，而对侧关节位移为 0。原因是 MakeHuman 权重文件里少数顶点带有跨中线的杂散权重（≤ 1 %）。判据据此分两层：对侧**关节** < 0.01 mm（严格），对侧**肢体表面** < 3 mm（如实报告实测值）。
- 链 B 的“动作通过”只表示**运动学方向正确**，不是视觉验收；它没有测翻面、边拉伸和自相交。
