# PAE-P1-001 — P1 开发计划 v0.2

本计划定义 P1 的执行顺序、检查点和工程纪律。技术范围以 `01-task-book-v0.2.md` 为准。

## 1. 总原则

- 先证明区域数据能在 Canonical 层可靠合并，再生成完整人物。
- 先建立最小完整 Android 链路，再增加 UV、Render Mesh 和证据系统。
- 每个阶段产生可运行代码、真实报告和失败清单。
- 拓扑问题不得带入渲染展开阶段。
- P1 不扩大面部、头发、服装、PBR 和 Corrective 范围。

## 2. 阶段 0 — 冻结与授权核对

### 输入

- 项目负责人授权。
- 并发写入结束确认。
- 当前 PoC-SM 工作区。

### 工作

1. 记录分支、HEAD、工作树、完整 diff、未跟踪文件。
2. 保存现有修改补丁和哈希。
3. 运行 Host 测试和 Android 构建基线。
4. 记录目标真机、SDK、NDK、JDK。
5. 形成修改白名单和保护清单。
6. 确认一次新 commit 的授权及提交方式。

### 退出条件

- 快照可复现。
- 现有未提交头脸代码和 v6/v7 证据受到保护。
- 白名单已确定。
- 基线失败已分类并保留。

基线失败若与 P1 无关，可作为已知问题保留，但不得在最终报告中隐藏；若阻塞 P1，先在白名单内修复。

## 3. P1-A1 — 数据模型与拓扑原型

### 目标

建立 Canonical Mesh、边界环、参数匹配、焊接、权重合并和拓扑报告的最小完整链路。

### 小型验证样例

| 样例 | 验证内容 |
|---|---|
| 两个不同密度边界环 | 弧长参数、锚点、方向、重采样 |
| 两个相交身体区域 | 融合、焊接、共享 Canonical ID |
| 两个不同权重区域 | BoneId 合并、Top-4、归一化 |
| 带 UV 接缝的曲面 | Canonical 不拆点、Render 正确拆点 |
| 简单弯曲区域 | LBS、权重连续性、姿态报告 |

### 实现顺序

1. 定义 Canonical 数据结构与边界引用。
2. 实现边界环锚点、方向和累计弧长。
3. 实现公共参数重采样与插值。
4. 实现 Canonical 顶点合并与索引重映射。
5. 实现静态拓扑报告。
6. 实现确定性权重合并。
7. 实现 Render-to-Canonical 最小映射测试。
8. 将样例整合进 Host 测试。

### 退出条件

- 边界配对确定性可复现。
- 焊接后为共享 Canonical ID。
- 拓扑报告能识别边界、非流形和退化面。
- 权重满足 BoneId、有限、Top-4 和归一化。
- 无长期独立 PoC 目录。

## 4. P1-A2 — 连续身体生成

### 区域顺序

1. 躯干与骨盆主体。
2. 肩部与上臂。
3. 髋部与大腿。
4. 小腿与脚。
5. 前臂与手。
6. 颈与头部轮廓。

### 每区域检查

- 静态拓扑。
- 边界匹配误差。
- 权重归一化和接缝连续性。
- 法线方向。
- 自交候选。
- 生成时间和内存。

### 实现策略

- 躯干、肩、髋使用分区域有界隐式场并联合融合。
- 头部轮廓、手、脚使用结构网格。
- 腕、踝使用严格边界连接。
- 初期使用较低采样分辨率，先验证连接和蒙皮。
- 每次提高分辨率都记录面数、时间、内存和关节表现。

### 退出条件

- 完整 Canonical Skin Shell 单连通、封闭。
- 无未处理非流形边、严重自交或开放边界。
- 完整身体权重可生成。
- 不依赖服装、头发或遮挡。

## 5. P1-A3 — 骨骼与 Android 观察

### 工作

1. 使用 Canonical 权重接入现有 22 骨骼 LBS。
2. 提供 Bind Pose、肩外展、肘屈曲、髋屈曲、膝屈曲。
3. 完成自由相机 Orbit/Pan/Zoom、距离限制和观察中心。
4. 接入 P1-A 最小 64B 预览路径。
5. 完成 Clay、Wireframe、Normal、Material ID、Weight Heatmap。
6. 在 Android 真机运行。

### 固定观察顺序

Clay 全身 → Wireframe 全身 → 正侧面轮廓 → 肩部近景 → 髋部近景 → 肘膝弯曲 → Weight Heatmap。

### 退出条件

- Android 上完整灰模可运行。
- 自由相机可稳定观察。
- 基础姿态可切换。
- 几何、权重和渲染问题可区分。

## 6. P1-A 检查点

只有以下条件满足才进入 P1-B：

- Canonical 拓扑报告合格。
- 权重报告合格。
- 完整身体在 Android 显示。
- Bind Pose 和基础关节弯曲可观察。
- 无依赖外观遮挡的结构缺陷。
- P1-A 最小预览路径不改变旧 64B ABI。

## 7. P1-B1 — UV 与 Render Mesh

1. 生成 Canonical UV Chart 和面角 UV。
2. 定义 UV、硬法线、材质接缝规则。
3. 展开 Render Mesh。
4. 生成 `renderToCanonical`。
5. 从 Canonical 派生 Render 权重。
6. 验证接缝两侧可追溯到同一 Canonical Vertex。
7. 检查 NaN/Inf、零面积 UV、重叠、越界和接缝错误。

设计性镜像或平铺重叠必须显式记录，不得简单全部判错。

## 8. P1-B2 — GPU 与法线验证

1. 保留旧 64B VBO/VAO。
2. 增加并行 UV VBO。
3. 增加版本化 PBR/预览 VAO。
4. 接入 UV Checker。
5. 比较 CPU/GPU Bind Pose 和代表姿态。
6. 覆盖非均匀模型缩放。
7. 验证世界法线使用逆转置。

P1-B 不要求完整 PBR，只要求数据路径和法线语义正确。

## 9. P1-B3 — 真机测试和证据包

- 固定七视角和主要关节近景。
- 固定姿态测试。
- Clay/Wireframe/Normal/UV/Material ID/Weight Heatmap 截图。
- 首次生成、GPU 上传、RSS、P95 帧时间。
- 源码、Mesh、APK、参数、相机、设备、日志关联。
- 原始测试日志、失败清单和未验证项清单。

## 10. 工程纪律

### 10.1 权威数据与缓存

代码审查必须询问：

> 这份数据是权威数据，还是某个阶段生成的缓存？

- Canonical 几何和权重是权威来源。
- Render Mesh、GPU Buffer、报告和 Corrective 展开数据是派生缓存。
- 缓存必须可按明确映射重新生成。

### 10.2 可失败检查点

每阶段输出实际报告，不使用单一 `valid=true` 代替检查。阶段失败时停止后续依赖阶段，不得继续上传 GPU 并把截图当成成功证据。

### 10.3 三角形与性能

不把 50k–150k 三角形当硬目标。初始低分辨率用于验证拓扑，整体正确后再局部细化。每次调整同时记录视觉、拓扑、姿态、生成时间和内存。

### 10.4 Android 优先观察

Host 测试不能代替 Android 观察。P1-A 就接入真机自由相机，不要等到 P1-B 才首次查看完整人物。

### 10.5 独立审查

实现 Agent 不得同时承担修改、审查和自我验收。关键网格、姿态数据、Shader 和真机证据由只读审查者复核，最终由项目负责人验收。

## 11. 提交与交付

P1 验证完成后允许创建一个新 commit。提交前检查：

- 只包含白名单文件。
- 不包含 `.workbuddy-ai/`、治理文件或未批准证据。
- 现有受保护修改已保留。
- 测试日志、失败清单和未验证项完整。
- 不 push、不 merge、不 rebase。

## 12. P1 最终集中验收

分别形成：

1. 拓扑结论。
2. 权重与姿态结论。
3. 视觉结论。
4. 真机性能结论。
5. UV/Render 与 CPU/GPU 专项结论。

任何一项没有证据，标记未验证。项目负责人独立作出 P1 整体验收决定。
