## 1. 任务目标

在 Android 真机中运行一个由 C++17 程序化规则生成的完整连续灰模人物，满足：

- 自然成人基本比例，不依赖服装、头发或阴影掩饰结构问题。
- 单连通、焊接完成的 Canonical Skin Mesh。
- 现有 22 骨骼、每顶点最多 4 个权重的 LBS。
- Bind Pose、肩外展、肘屈曲、髋屈曲、膝屈曲等基础姿态。
- 自由旋转、缩放、平移相机。
- Clay、Wireframe、Normal、UV Checker、Material ID、Weight Heatmap 调试视图。
- 真实 UV 生成、Render Mesh 展开和 GPU 上传。
- 拓扑、权重、姿态、渲染数据、视觉和真机性能的独立报告。

P1 的交付不是新框架或算法报告，而是 Android 上真实可观察、可弯曲、可测量的连续灰模人物。

## 2. 范围

### 2.1 纳入范围

- 头部轮廓、颈、躯干、骨盆、双臂、双手、双腿和双脚。
- 连续主体隐式场与结构网格的混合生成。
- 肩、颈、髋等重要区域联合融合或可靠边界连接。
- 腕、踝及结构网格边界的确定性匹配与焊接。
- Canonical Mesh、Render Mesh、`renderToCanonical`。
- Canonical 权重合并、Top-4、归一化和热图。
- P1-A 最小 64B 预览路径。
- P1-B 并行 UV VBO、版本化 VAO 和 UV Checker。
- CPU/GPU 位置与法线一致性、非均匀模型缩放测试。
- Android 真机固定姿态、七视角、性能和证据包。

### 2.2 不纳入范围

- 最终解剖级头脸、完整眼睑/鼻孔/唇部系统。
- 最终头发 Ribbon/Cards。
- 两套正式服装。
- 完整 GGX PBR、皮肤 SSS。
- 布料或肌肉模拟。
- 全身 Corrective Shapes。
- 表情系统。
- 多人物、多体型或通用几何框架重构。

Corrective 仅要求 P1 的 Canonical ID、权重和 Render 映射可支持后续实现；原型和正式实现属于 P4。

## 3. 冻结约束

除非另有正式授权，不得改变：

- C++17、Android NDK、OpenGL ES 3.0。
- 22 骨骼定义及 BoneId 0–21。
- GPU Skinning UBO[22]。
- 每顶点最多 4 个骨骼影响。
- 现有 64-byte GPU Vertex Packing。
- 已冻结 JNI ABI。
- 现有旧版 GPU 顶点路径。

新数据只能通过并行 VBO、独立 VAO 或兼容扩展实现。不得引入 JavaScript Runtime、Three.js 或在线 AI Runtime。

## 4. 核心数据合同

### 4.1 Canonical Skin Mesh

Canonical Mesh 是几何拓扑、边界焊接、蒙皮权重、姿态验收和未来 Corrective 的唯一逻辑来源。

- 不允许因 UV 或渲染法线拆点。
- Skin Shell 必须单连通、封闭、无未处理非流形边和严重自交。
- 眼球、头发、服装等辅助几何不计入 Skin Shell 封闭性统计。

### 4.2 Render Mesh

Render Mesh 是 GPU 绘制数据，允许因 UV Chart、硬法线、材质或平滑组拆点。

必须满足：

```text
renderToCanonical[renderVertexId] = canonicalVertexId
```

多个 Render Vertex 可以映射到同一 Canonical Vertex。Render 权重必须从 Canonical 权重派生，不得独立编辑。未来 Corrective 也以 Canonical Vertex ID 为逻辑索引，GPU 上传时按 Render Vertex 展开复制。

### 4.3 P1-A 临时预览路径

P1-A 在完整 Render Mesh 建立前，使用从 Canonical Mesh 直接派生的最小 64B 预览路径，不拆 UV。该 GPU 数据只是缓存，不得成为第二套几何或权重来源。P1-B 再建立完整 Render Mesh。

## 5. 边界、焊接与权重

### 5.1 边界参数

- 使用 Bind Pose 下沿参考边界环的归一化累计弧长参数。
- 每个环定义起始锚点、正方向、区域 ID、配对 ID 和方向转换。
- 两侧采样密度不同时，在公共参数位置重采样和插值。
- 匹配后必须共享 Canonical Vertex ID，不能只保留同坐标顶点。
- 焊接容差使用尺度相关候选公式，并通过实际精度测试确认。

### 5.2 权重合并

1. 按 BoneId 合并两侧影响。
2. 初版等权平均。
3. 删除无效或接近零影响。
4. 按权重降序保留最多 4 个。
5. 重新归一化。
6. 检查 BoneId、有限值、非负和权重和 `1 ± 0.001`。
7. 输出接缝权重连续性和热图。

若等权平均造成明显跳变，必须记录问题并使用局部过渡权重，不得无证据改变规则。

### 5.3 固定构建顺序

1. 区域几何生成。
2. 边界环建立及参数化。
3. 边界匹配和重采样。
4. Canonical Mesh 焊接及静态拓扑检查。
5. Canonical 蒙皮权重合并和验证。
6. Canonical 法线与 UV Chart/面角 UV 数据生成。
7. Render Mesh 接缝拆分和数据展开。
8. Render-to-Canonical 映射验证。
9. GPU Buffer 和 VAO 上传。
10. Android 渲染及姿态验证。

不得在 UV/法线拆点后混同 Render 与 Canonical 拓扑。

## 6. 实施阶段

### 阶段 0 — 工作区冻结与授权核对

- 并发写入已结束。
- 记录分支、HEAD、工作树、完整 diff、未跟踪文件和构建基线。
- 保护未提交头脸代码、v6/v7 证据及现有修改。

- 核实 AUTH-08、DEC-05、CAS、Gate 状态。

阶段 0 未完成不得修改 P1 生产源码。

### P1-A1 — 数据模型与拓扑原型

实现 Canonical Mesh、边界环、弧长参数、重采样、焊接和拓扑报告。使用小型测试网格验证：

- 不同密度边界环。
- 两个相交身体区域。
- 两个不同权重区域。
- 一条带 UV 接缝的曲面。
- 一个简单弯曲区域。

测试样例必须整合进正式测试或生产路径，不得长期成为独立 PoC。

### P1-A2 — 连续身体生成

按躯干 → 肩/上臂 → 骨盆/大腿 → 小腿/脚 → 前臂/手 → 颈/头轮廓顺序增加区域。每增加重要区域运行拓扑和权重检查。

### P1-A3 — 骨骼与 Android 观察

接入 22 骨骼 LBS、Bind Pose、基础关节弯曲、自由相机和 Clay/Wireframe/Normal/Material ID/Weight Heatmap。先确保 Android 上完整身体可从多角度观察。

### P1-A 检查点

- Canonical 拓扑和权重报告完成。
- 完整灰模在 Android 运行。
- 基础姿态可观察。
- 不依赖服装或头发。
- 拓扑缺陷未解决时不得进入 P1-B。

### P1-B1 — UV 与 Render Mesh

生成 UV Chart、面角 UV、Render Mesh 和 `renderToCanonical`，验证接缝顶点来源。

### P1-B2 — GPU 与法线验证

增加并行 UV VBO 和版本化 VAO，保留旧 64B 路径。比较 CPU/GPU 位置与法线，覆盖非均匀模型缩放。

### P1-B3 — 真机测试和证据包

完成固定姿态、七视角、近景、性能数据和证据关联。

### P1 最终集中验收

由项目负责人独立检查拓扑、权重、姿态、视觉、渲染数据和真机性能。AI 只提交报告，不自行宣布验收通过。

## 7. 开发纪律

- 先最小完整链路，不先扩建平台。
- 不以调整肩宽、胸围、头身比或肤色掩饰几何问题。
- 不在 P1 扩大面部、头发和服装范围。
- 每阶段输出实际报告；阶段失败时停止后续依赖阶段。
- 不过早优化三角形数量；每次分辨率调整记录时间、内存、面数和关节表现。
- 尽早接入 Android 自由相机。
- 单写入者、多只读审查者；审查 Agent 不得自动修复源码。
- 询问每份数据是权威来源还是可重建缓存。

## 8. 验收方法

### 8.1 静态拓扑

检查 Canonical Skin Mesh：

- 连通组件 1。
- Boundary Edges 0。
- Non-manifold Edges 0。
- 无超阈值退化三角形。
- 绕序和法线方向一致。
- 无未处理严重自交或开放边界。

自交使用空间加速宽相位和窄相位，明确排除正常相邻三角形。报告记录算法、阈值和异常数量。

### 8.2 权重

- BoneId 0–21。
- 最多 4 个有效影响。
- 有限、非负、归一化。
- 接缝连续性报告和热图。

### 8.3 姿态

候选角度集 `0° / 30° / 60° / 90° / 120°`，按关节有效范围执行。报告包含关节角、矩阵、截面周长/面积、局部体积、法线翻转、对应边最大分离、左右偏差和穿透。

局部体积必须使用明确闭合区域。`0.80–1.20` 仅为实验起点，不是最终标准。

### 8.4 CPU/GPU 与法线

固定网格、矩阵和姿态比较：

- Bind Pose。
- 肘、膝代表角度。
- 非均匀模型缩放。
- 最大/平均位置误差。
- 最大法线角差。
- 异常法线数量。

阈值必须在测试前确定，不得看到结果后反复调整。世界法线使用模型矩阵线性部分的逆转置。

### 8.5 UV 与 Render Mesh

- Render Vertex 均映射到合法 Canonical ID。
- UV 无 NaN/Infinity。
- 无非预期零面积 UV、重叠和越界。
- 设计性镜像/平铺重叠必须记录。
- UV Checker 显示真实 UV。
- 接缝可追溯到同一 Canonical Vertex。
- 新旧 GPU 路径完成兼容性检查。

### 8.6 视觉

Android 真机提供正面、背面、左右侧面、左右 45°、后侧角度及全身/关节近景。重点检查成人轮廓、肩胸/腰腹/骨盆/髋部连接、手腕脚踝、裂缝、尖刺、翻转和基础姿态。

不得使用商业人物图片、现成模型或预渲染视频冒充项目结果。

### 8.7 性能

记录区域场初始化、融合、提取、焊接、权重、UV、GPU 上传、首次生成总耗时、Native RSS、临时内存和固定条件 P95 帧时间。记录设备、Android、GPU、GLES、分辨率和温度状态。单机数据不得推断为全平台结论。

## 9. 证据包

至少包含：

- Git HEAD、工作树状态、完整 diff 哈希。
- 构建配置、NDK/SDK/JDK 版本和构建日志。
- APK SHA-256。
- Canonical/Render Mesh SHA-256。
- 人物参数、随机种子、生成器版本。
- 骨骼姿态参数、相机和光照参数。
- 设备与 GLES 信息。
- 原始测试日志、pass/fail 计数。
- 失败项清单。
- `NOT RUN / UNVERIFIED / PARTIALLY VERIFIED` 清单。
- 原始截图和七视角对照。

Host 审计可复用同一 Mesh 哈希和算法，但不能替代 Android 真机证据。

## 10. 停止条件

出现以下情况立即停止相关写入：

- 工作区出现并发写入或基线无法复现。
- 修改超出白名单或授权范围。
- Canonical 无法形成可靠拓扑。
- 边界错配、权重双权威或映射不稳定。
- 新 GPU 路径破坏旧 64B ABI。
- 拓扑、权重、姿态、CPU/GPU、Android 构建或运行失败。
- 源码、Mesh、APK 和截图无法对应。

停止后保留现场、日志和 diff，不清理、不回滚他人修改，形成问题报告等待负责人决定。
