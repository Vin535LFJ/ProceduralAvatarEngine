## 2. 评价矩阵：8 个质量维度 × 7 个视角

### 2.1 8 个质量维度定义

**这是本次修订的主体。** 每个维度有：定义、观察对象、观察位置、判定方式、是否一票否决。

---

#### D1 — 人体比例（Proportion）

`[定义]` 头身比、肩髋比、胸腰比、腰盆比、肢段长度比等**整体比例关系**是否自然可信、是否符合目标体型的风格定位。

- **观察对象**：整体轮廓的分区比例，非局部细节。
- **观察位置**：front / side / back 三个基准视角。
- **判定方式**：负责人对参考图逐项标注"目标区间" → 与生成模型的实测比例对照。
- **与几何细节的关系**：**比例正确 ≠ 形态正确**。D1 通过不能推及 D2。
- **一票否决**：不单独否决，但 D1 严重失真会使全部后续维度的结论失去参照意义。

`[INFERENCE/PARTIALLY VERIFIED]` D1 必须独立于 D2，是因为 R3 的失败模式恰好属于 D1/D2（包络上胸宽度差 13.5 cm），而 R2 的 E2 0.98 mm 优秀却完全没覆盖"形态是否像人体"——这说明数值指标无法替代 D1/D2 的主观判断。

---

#### D2 — 解剖结构（Anatomy）

`[定义]` 胸廓、腹壁、骨盆、肩带、腋窝的**解剖关系**是否成立：肩根是否为连续的人体结构而非拼接件、腋窝是否形成真实凹面、肋弓/腰线/髂嵴是否可读。

- **观察对象**：结构关系的存在性与合理性。
- **观察位置**：front-45-left / side-left / side-left-30up / back-45-right（结构最易读的四个视角）。
- **判定方式**：负责人对参考图标注结构特征 → 逐特征核对生成模型。
- **数值辅助**：landmark 位置误差（G2 实测 R3 mean 54.4 mm / max 126.8 mm）。
- **一票否决**：**是**。独立肩球、圆管接缝、mesh append 痕迹、腋窝填平 → `REJECTED`。

`[FACT/VERIFIED]` 现有 rubric §3.4 的三条一票否决项全部归入 D2。

---

#### D3 — 曲面连续性（Surface Continuity）

`[定义]` 表面在区域交界处的**曲率与法线连续性**，不含拓扑问题（那是 D4）。

- **观察对象**：接缝带上的高光走向、折痕、台阶、鼓包、凹陷。
- **观察位置**：side-left-30up（肩带顶面）、front-45-left（腋窝前缘）、side-left（腰背过渡）、back（腰背）。
- **判定方式**：视觉 + 数值辅助。
- **数值辅助**：接缝最大二面角（G2 实测 R1/R2 47.66°、R3 16.13°，合同阈值 **≤5°** —— 这是合同已有值，非新增阈值）。
- **一票否决**：**是**。肩根/腋窝出现穿透或自交 → `REJECTED`。

`[FACT/VERIFIED]` ≤5° 是 SPEC 既有合同值（§13 对 smooth seam），是当前唯一可判 FAIL 的数值项。其余 D3 数值门槛为 TBD。

---

#### D4 — 拓扑质量（Topology Quality）

`[定义]` 网格拓扑**是否适合动画驱动**。静态外观与拓扑质量必须分开评价。

- **观察对象**：
  - 四边形流线是否沿肩—腋—肘、髋—膝方向连续；
  - 关节环（shoulder loop / elbow loop / knee loop）是否存在且位置合理；
  - 面片质量：长宽比、最小内角、sliver 数量；
  - 连通性：组件数、边界边、非流形边、退化三角形；
  - 参数变化下的**拓扑稳定性**（顶点 ID 与面邻接是否恒定）。
- **观察位置**：Wireframe / Topology 视图（见 §6 D 型图）。
- **判定方式**：Wireframe 目视 + 数值辅助。
- **数值辅助**（G2 实测，均为实测值非阈值）：

  | 指标 | R1 | R2 | R3 |
  |---|---|---|---|
  | sliver 数 | 30 | **0** | 20 |
  | 平均最小内角 | 70.1° | 83.0° | 86.4° |
  | 正交 quad 比 | 0.637 | 0.935 | 1.000 |
  | 顶点 ID 跨参数组稳定 | **否**（5108→5234→5314） | 是 | 是 |
  | 未登记 boundary / non-manifold / degenerate | 0 | 0 | 0 |

- **一票否决**：**是**。non-manifold > 0、degenerate > 0、组件数 ≠ 1（登记 crop 除外）→ `REJECTED`。
- **注意**：已登记的肩根 crop 边界（32 条边）**不是缺陷**，不得据此判 FAIL。

`[FACT/VERIFIED]` 现有生产 `TopologyReport` 只能数 boundary edge，无法区分"已登记 crop"与"未登记裂缝"；区分能力由 G2 新增的 `TopologyAudit` 提供。

---

#### D5 — 骨骼驱动（Skeletal Rigging）

`[定义]` 骨骼层级、bind pose、权重绑定是否**合法且合理**。

- **观察对象**：bind pose 下网格是否处于预期姿态；骨骼位置与体表 landmark 是否对应；权重是否平滑过渡。
- **观察位置**：A-Pose 静置图 + 骨骼叠加热图。
- **判定方式**：视觉 + 权重合法性数值。
- **数值辅助**（G2 实测）：三路线权重全部合法（≤4 影响骨、非负、和 = 1±1e-3、骨 ID ∈ [0,21]）；PoC 权重赋值器与生产实现逐顶点比对 **0/5108 不一致**；合成刚体探针 22/22 零误差，bind residual ≤2.4e-7。
- **一票否决**：权重非法（超 4 影响骨 / 负权 / 和偏离 >1e-3 / ID 越界）→ `REJECTED`。
- **未决**：`[OPEN QUESTION]` GPU 侧权重绑定/parity 仍 `UNVERIFIED`。按 SPEC §11.1 这**不是** G2 的 kill 项，但在 P2 装配前必须补测。

---

#### D6 — 动作变形（Deformation Under Motion）

`[定义]` 关节弯曲时**表面的体积与形状保持**。这是最容易被静态图掩盖的一维。

- **观察对象**：肘屈曲 90°、肩前屈 90°、髋屈曲 90° 时的肘窝凹陷、腋窝褶皱、肩部塌陷、肢体体积损失。
- **观察位置**：Joint Deformation Comparison 图（见 §6 E 型图）。
- **判定方式**：并排对比 + 负责人对参考图的期望形态标注。
- **数值辅助（可选）**：顶点位移统计、局部体积变化率。
- **一票否决**：**否**（P1 阶段未要求动作验收时），但**肢体可见体积塌陷**应记为高优先级缺陷。
- **未决**：`[OPEN QUESTION]` P1 是否包含动作验收，取决于 AUTH 范围。若不包含，D6 标记 `NOT RUN` 而非 `PASS`。

`[RECOMMENDATION]` D6 单列的原因：任务书明确"不能因为模型静态外观漂亮，就认为它适合动画驱动"。LBS 的肩肘体积损失是已知风险，SPEC §9 允许在动作数据证明后再评估 DQS/Corrective/LVP。

---

#### D7 — 视觉完成度（Visual Finish）

`[定义]` 在几何与拓扑合格的前提下，**表面观感**的质量：光影层次、材质响应、轮廓线、细节密度。

- **观察对象**：Clay 渲染的明暗层次、轮廓是否有"低模棱线"、材质是否掩盖或放大缺陷。
- **观察位置**：全部 7 视角 + 材质变体。
- **判定方式**：负责人对参考图标注完成度层级。
- **一票否决**：**否**（除非出现"明显低模/玩具感"这一被明确排除的方向 → 归入 D2）。
- **边界声明**：`[FACT/VERIFIED]` **高品质视觉目标不等于必须使用高面数网格**。D7 高分不得被用作增加面数的理由；D7 低分也不得通过引入外部贴图资产解决（违反生产约束）。

#### D8 — 运行性能（Runtime Performance）

`[定义]` 在**目标 Android 低性能设备**上的生成时间、内存、三角形数、GLES3 帧率。

- **观察对象**：几何生成耗时、峰值内存、渲染帧率。
- **判定方式**：设备实测（真机，非模拟器）。
- **一票否决**：**否**。
- **未决**：`[OPEN QUESTION]` 目标帧率与预算尚无负责人批准值；当前无任何设备实测数据（G2 报告已如实记录）。
- **边界声明**：`[FACT/VERIFIED]` 不得为了追求静态视觉效果而破坏现有技术约束（任务书第八节）。

### 2.4 五 Gate 分离：验收对象与替代禁区

`[FACT/VERIFIED — 负责人指示]` **不要把 P1 的几何验收和最终渲染品质混成一个 Gate。** 每类验收对象有明确的"应该验证什么"与"不应该用什么代替"：

| Gate | 验收对象 | 应该验证什么 | **不应该用什么代替** | 承载维度 | 本轮是否评 |
|---|---|---|---|---|---|
| **G-P1-GEO** | P1 人体几何 | 解剖比例、曲面连续性、人体体积 | 高质量皮肤贴图 | D1, D2, D3 | **是** |
| **G-P1-TOPO** | P1 拓扑 | 肩根、腋下、胯部、关节结构 | 单纯统计面数 | D4 | **是** |
| **G-P1-ANIM** | P1 动画 | 关节弯曲、体积保持、变形连续性 | 静态 T-Pose | D5, D6 | **是**（姿态轴） |
| **G-P2-MOD** | P2 模块化 | 服装、发型、配件独立切换 | 单张穿着完整服装的效果图 | Layer C | **否**（P2 阶段另立 rubric） |
| **G-FINAL-VIS** | 最终视觉 | 整体角色完成度、材质、光照 | 单纯几何测试通过 | D7, D8 | **部分**（几何通过 ≠ 视觉通过） |

`[RECOMMENDATION]` 这条分离在 rubric 里的**具体实现**是三条规则：

- **R-1（正交判定）**：一个 Gate 的 PASS **不能**被另一个 Gate 的 PASS 推导。`G-P1-GEO` PASS 不等于 `G-P1-TOPO` PASS，也不等于 `G-FINAL-VIS` PASS。
- **R-2（禁止替代）**：每个 Gate 的"替代禁区"里的东西，**即使做得再好也不能用来满足该 Gate**。例如：给人体刷一张高质量皮肤贴图，**不能**用来满足 `G-P1-GEO`（"曲面连续性"必须由几何本身证明）。
- **R-3（分表签署）**：五个 Gate **分别签署**，不合成一个"视觉 Gate"结论。这与 H-6（禁止汇总）一致。

`[INFERENCE]` R-2 有一个具体易犯的错误：给模型加一张带环境光遮蔽的皮肤贴图，会**在渲染图上掩盖**曲面缺陷、接缝台阶、腰臀断裂。评审者看到"漂亮"就判 GEO PASS，而实际几何仍在失败——这正是当前 G2 中 R3 的处境（上胸缺口 13.5 cm，靠任何贴图都补不上，但渲染图上可能看不出来）。

`[RECOMMENDATION]` 补充一条判定顺序规则：**R-3a — `G-P1-GEO` 未通过时，`G-FINAL-VIS` 不予受理**（不是判 FAIL，是不进入评审）。理由：几何不成立时，材质与光照的表现没有诊断价值。这与 R-1 不同——R-1 是"不互相推导"，R-3a 是"下游不予受理"，两者不冲突。

## 3. 视角与姿态的正交化（本次修订最重要的结构性建议）

### 3.1 问题

负责人本轮要求的 7 个视角是：Front / Front 3/4 / Side / Back / Back 3/4 / **T-Pose** / **A-Pose**。
现有 rubric 的 7 个视角是：front / front-45-left / side-left / side-left-30up / back / back-45-right / front-30up。

两者**不是同一个东西**。现有 7 个是**相机方位**；T-Pose / A-Pose 是**角色姿态**。姿态改变的是骨架与蒙皮状态，不是相机位置。

`[FACT/VERIFIED]` T-Pose 与 A-Pose 的几何差异**必须经过骨骼与蒙皮**才能产生——同一套静态网格换个机位拍出来不会变成 T-Pose。这意味着姿态轴要求评估链路上**必须先有可用的骨架 + 权重 + CPU 变形**，这正是 G2 已经验证过的部分（权重合法性 ✅、CPU 侧变形 ✅、GPU parity 未验）。

### 3.2 建议的两轴设计

```
视角轴（Camera azimuth × elevation）—— 7 个固定机位
    front / front-45-left / side-left / side-left-30up
    back / back-45-right / front-30up

姿态轴（Posture）—— 3 个姿态
    P0 = bind pose（项目定义的 bind pose）
    P1 = A-Pose（双臂自然下斜）
    P2 = T-Pose（双臂水平展开）
```

**证据矩阵** = 视角 × 姿态。全部笛卡尔积并不可行（7×3×3路线×3参数组 = 189 张/组）。

`[RECOMMENDATION]` 最小充分集合：

| 用途 | 视角 | 姿态 | 数量 |
|---|---|---|---|
| **几何/解剖/连续性**（D1/D2/D3/D7） | 现有 7 机位 | **仅 bind pose** | 7 |
| **驱动/变形**（D5/D6） | front / side-left / back-45-right / side-left-30up | bind / A-Pose / T-Pose + 肘屈曲90° + 肩前屈90° | 4 视角 × 5 姿态 |
| **拓扑**（D4） | 无视角（正交/俯视叠加） | bind | wireframe + 肩/肘拓扑带特写 |

理由：几何质量在 bind pose 下判定（骨骼不引入额外几何），驱动质量必须在多姿态下判定。两者分离后，每张图只回答一个问题，可审计性显著提升。

### 3.3 现有实现的差距（必须先补）

`[FACT/VERIFIED]` G2 已实现的 `CameraProtocol` / `ClayRenderer` 当前有**两个硬限制**：

1. **躯干带裁剪**：clay 渲染与数值轮廓都裁剪到 PoC-A 躯干带（`yMin`/`yMax`），**无法出全身图**，因此 T-Pose/A-Pose 全身图当前无法产出；
2. **无姿态驱动**：渲染器只接受静态 `MeshData`，不接受蒙皮后的顶点集，也没有姿态参数。

`[RECOMMENDATION]` 因此新增 `05-posture-pose-draft.md`（草案，与本文件同批提交）描述姿态轴的最小实现：
在现有 `renderClayView` 前增加一步 `applyPose(mesh, skeleton, pose) -> posedMesh`（CPU 侧，复用 `Skinning.cpp` 已有的 `cpuSkinPositions`），并把裁剪带参数化（`band = none | torso`）。**这属于协议设施扩展，不是新几何算法**。

`[RECOMMENDATION]` A-Pose 与 T-Pose 的**确切角度**（A-Pose 手臂下斜多少度、T-Pose 是否严格水平）属于形态定义，需要负责人或 §4 的参考图确定，我不自行设定数值。
